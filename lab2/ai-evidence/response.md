1. Recommend a Python FastAPI modular monolith, PostgreSQL, and a thin browser UI using server-rendered HTML or a small JavaScript client. FastAPI’s type-based validation, automatic OpenAPI documentation, and dependency system suit a small course API; security dependencies can express authentication and role or scope checks: https://fastapi.tiangolo.com/features/ and https://fastapi.tiangolo.com/advanced/security/oauth2-scopes/. This is a discussion recommendation; the team’s existing experience has not been supplied.

2. Map the conceptual entities to normalized PostgreSQL tables: User, EVProfile, ChargingPlan, PlanVersion, OfficialSnapshot, RouteEstimate, Recommendation, Connector, ChargingStation, IssueReport, and ModerationDecision. Foreign keys connect ownership and composition; primary-key, UNIQUE, NOT NULL, and CHECK constraints protect identifiers, cardinality, and ranges. PostgreSQL documents these integrity constraints here: https://www.postgresql.org/docs/current/ddl-constraints.html. Enforce “only a Driver owns a profile or plan” in the service authorization check too; a foreign key alone does not understand the role value.

3. Treat PlanVersion as append-only data. Reconfiguration or manual refresh inserts a version and its RouteEstimate/Recommendation children, records the exact OfficialSnapshot and copied assumptions, then updates the plan’s current-selection pointer in one PostgreSQL transaction. Transactions provide all-or-nothing visibility: https://www.postgresql.org/docs/current/tutorial-transactions.html. Expose no update or delete operations for historical versions; keep selection mutable at ChargingPlan level. A small repository layer and deterministic tests are enough; event sourcing adds avoidable complexity.

4. Define small MapProvider and StationProvider interfaces, with OneMap, LTA DataMall, cached, and Demo Fixture adapters returning one canonical shape. Persist source, observed/retrieved timestamps, and data state so ranking is provider-independent. The recommendation service calculates feasibility and ranks all candidates first, then reads active verified, unexpired faults, marks affected recommendations FILTERED_FAULT, and fills the shortlist from next-ranked unmarked candidates (up to three). Pending reports never enter this exclusion query; ModerationDecision records actor, reason, action, timestamp, and resulting status. Put moderator endpoints behind a server-side role dependency, and use a maintained password-hashing library plus TLS at deployment.

5. Keep manual refresh as an explicit endpoint. Avoid microservices, GraphQL, a message broker, Redis, and continuous monitoring. For a single-process local demo, SQLite with the same schema and server-rendered pages is simpler; PostgreSQL is preferable for shared testing and relational constraints.
